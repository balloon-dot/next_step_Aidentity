# Профи — прототип профессионального профиля

Публичный сайт: https://profi-map-demo.flowyjelly32.chatgpt.site

## Сценарий

Владелец создает аккаунт по логину и паролю, формирует квадратную карту Вороного и фиксирует результат. Карта сохраняется в аккаунте в D1. «Поделиться для оценки» создает серверное приглашение с неизменяемой копией этой карты. Анкета, контакты и PDF не включаются в приглашение.

Знакомый открывает приглашение с любого устройства, указывает имя и фамилию, затем корректирует готовую карту и вложенные качества. Допускается отправка без изменений. Итоговые карты и имена сохраняются в D1. Повторные ответы с того же устройства/аккаунта или с тем же нормализованным именем в рамках приглашения не увеличивают число участников. Это проверка повторов, а не верификация личности.

В профиле и результатах собственная диаграмма показана сверху, усредненная карта знакомых — снизу. До двух участников сервер возвращает только счетчик и имена, без значений ответа. После второго участника усредняются все итоговые баллы кластеров и качеств, включая оставленные без изменений. Новые ответы обновляют средние значения. Самооценка не изменяется. Версии приглашений и их ответы хранятся отдельно.

Кластеры имеют баллы 1–30. Сумма — 330. Площади пропорциональны баллам. Когда кластер достигает границы 1 или 30, остаток распределяется между остальными доступными кластерами. Вложенные качества имеют независимые оценки 1–30.

Перечень из 33 кластеров и четырех качеств на кластер пока примерный (`examples-v1`), реальные данные будут предоставлены отдельно. Ссылки сохраняют версию перечня; несовместимые версии не объединяются. Старые ссылки со снимком `#result=` остаются для просмотра, для сбора ответов нужно создать новое приглашение.

## Аккаунты и данные

Пароли: PBKDF2-SHA256 (100000 итераций, случайная соль), без хранения открытого пароля. Сессии: случайный 256-битный токен в HttpOnly/SameSite=Lax/Secure cookie; в D1 хранится только SHA256 токена, срок 30 дней. Вход ограничен по числу попыток. Личный кабинет и сводки авторизуются на сервере через эту сессию. Внешние платформенные заголовки не заменяют вход в аккаунт.

Локальные черновики разделены по аккаунтам. Личная анкета остается в браузере, PDF — в IndexedDB; этот прототип не синхронизирует их между устройствами. Зафиксированные карты, аккаунты, приглашения и ответы сохраняются на сервере. Восстановление пароля пока не реализовано.

## Разработка

Vinext + Vite + Cloudflare Worker + D1. Интеграция Sites сохранена в `build/sites-vite-plugin.ts`. Идентификатор сайта и логическая привязка D1 находятся в `.openai/hosting.json`. Схема — `db/schema.ts`, миграции — `drizzle/`. Не менять уже примененные миграции.

- `npm ci` — зависимости.
- `npm run db:generate` — следующая миграция после изменения схемы.
- `npm test` — расчет площадей, изоляция самооценки, сводки, порог двух ответов, регистрация/вход/выход и проверки доступа на SQLite.
- `npm run build` — артефакт `dist/` со схемой публикации Sites.
- `node scripts/http-smoke.mjs` — полный HTTP-сценарий через локальный построенный Worker; нужны заранее примененные локальные миграции D1. Проверяет двух независимых оценщиков и повторный вход.

Публикация: зафиксировать и отправить исходники, упаковать построенный `dist/`, сохранить версию Sites и развернуть ее с прежним публичным доступом. Локальные базы и секреты не входят в архив.

## Режим оценщика (v0.5)

В приглашении хранится отдельное имя владельца профиля (`owner_name`), которое видно в закрепленном напоминании над картой и внутри кластера. Если имя еще не указано, при создании ссылки владелец заполняет его; контакты, логин и PDF в приглашение не добавляются. Смена имени обновляет существующее приглашение, не сбрасывая собранные ответы.

Оценщик переключается между Вороным и редактируемым числовым хвостом; оба вида используют одну карту и одну шкалу. Вложенные качества доступны в обоих видах. Прямые изменения оценщика отмечаются оранжевым, включая карточку измененного качества и его кластер. Оценки владельца и автоматическое перераспределение соседей не считаются прямыми правками оценщика. Черновик хранит значения, отметки и выбранный вид в sessionStorage для конкретного приглашения.

## Исправление редактирования хвоста (v0.6)

Ранее после каждого +/− список пересортировывался и полностью перерисовывался. Несколько кликов в одной позиции попадали в кнопки разных кластеров. Теперь порядок строк закреплен во время правок, значения обновляются на месте. «Обновить рейтинг» сортирует по актуальным баллам. «Снять выделение» и Escape убирают текущий выбор, сохраняя внесенные оценки; цвет продолжает отмечать историю правок.

`PLAYWRIGHT_BROWSERS_PATH=<путь> node scripts/tail-browser-check.cjs` запускает проверку в Chromium: воспроизводит баг старой версии, проверяет повторные клики в одни координаты в роли владельца и оценщика и на мобильном экране, снятие выбора, пересортировку и совпадение значений с Вороным. Проверка использует локальные фикстуры, не создает аккаунты или ответы на опубликованном сайте, завершает свой сервер и браузер после работы.
